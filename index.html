01 · How it's built

Four stages, one pipeline

Synthetic data stands in for real transaction logs (never available for a portfolio project) — everything downstream is built the way it would be in production.

STAGE 01

Synthetic Ledger

20,000 transactions across 2,000 users with four injected fraud patterns — SIM swap, account takeover, smurfing, mule velocity — 30% deliberately stealthy to avoid a trivially separable dataset.

numpy · pandas
STAGE 02

Feature Engineering

Rolling per-user and per-recipient windows computed with strict time-causality — velocity, amount z-scores, device/SIM change flags, recipient age — no peeking at the future.

bisect · rolling windows
STAGE 03

Risk Model

Gradient-boosted trees trained on a time-based split, evaluated on precision-recall and precision@K — the metrics that map to an analyst team's real review capacity.

XGBoost-class model
STAGE 04

Explainability

Every flagged case gets a plain-language reasoning summary built from its contributing risk factors — the layer an analyst actually reads before acting.

Claude API — live

04 · Methodology

What's real and what's illustrative

All transaction data on this page is synthetic — generated to mimic Nigerian mobile money behavior, not sourced from any real platform or user. The risk model is a genuine gradient-boosted classifier trained on this data with a time-based split to avoid leakage; the metrics shown are its actual held-out performance, not illustrative numbers. The bulleted "Signals" in the case review panel are computed directly from the model's own top features. The "Analyst Note" beneath it is a live call to the Claude API — Claude is given the same computed signals and writes the plain-language explanation in real time, which is why it takes a moment to appear.
